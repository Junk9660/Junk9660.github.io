UE5 C++ Save Interface & GUID

Engine Version: Unreal Engine 5.6 | Language: C++

Architecture Context & Baseline

Use of GUID to save and load data to the right actor, as well as checking if the actor was spawned during runtime.

2. Key Technical Features

  • GUID Identification: Allow clear identification of each actor in the level by using FGuid SaveActorID.
  • Interface Driven: ISaveInterface allow to pull and set information in the different actors.
  • Destroyed Actors Tracking: Use of EndPlay() to register the SaveActor ID in an array of destroyed actors, preventing loading them.
  • Serialization : Use of FObjectAndNameAsStringProxyArchive to serialize only variables tagged with UPROPERTY(SaveGame), removing manual handling.

3. Technical Deep-Dives

	}

#endif
//Interface calls
FGuid ABaseActor::GetActorId_Implementation()
{
	return SaveActorID;
}

void ABaseActor::SetActorId_Implementation(const FGuid& NewID)
{
	if (SaveActorID.IsValid())
	{
		SaveActorID.Invalidate();
	}
	SaveActorID = NewID;
}
Interface Driven — Decoupled system with interface

Use of Interface to retrieve and set back data without hard casting.


FActorSaveData ABaseActor::GetSaveData_Implementation()
{
	FActorSaveData ActorSaveData;
	ActorSaveData.Transform = GetTransform();
	ActorSaveData.ActorClass = this->GetClass();
	ActorSaveData.bIsRuntimeSpawned = bIsSpawnedAtRunTime;
	UInv_LootComponent* LootComp = FindComponentByClass();
	if (LootComp)
	{
		ActorSaveData.FInv_LootData = LootComp->GetInventoryList();
	}

	return ActorSaveData;
}
void ABaseActor::OnLoadGame_Implementation(const UMySaveGame* SaveDataObject)
{
	UInv_LootComponent* LootComp = FindComponentByClass();
	if (LootComp)
	{
		FActorSaveData ActorSaveData = SaveDataObject->SavedActorMap.FindRef(SaveActorID);
		LootComp->SetInventoryList(ActorSaveData.FInv_LootData);
	}
}
Destroyed Actors Tracking — Prevent loading destroyed actors

SaveSubsystem tracks destroyed actors within an TArray DestroyedActorGuids;.

//SaveSusbystem.cpp
//Called by Actor's EndPlay()
void USaveSubsystem::RegisterDestroyedActor(const FGuid& ActorGuid)
{
	if (!CurrentSave) return;
	CurrentSave->WorldState.DestroyedActorGuids.AddUnique(ActorGuid);
	UE_LOG(LogSaveInterface, Warning, TEXT("Actor with following ID %s has been destroyed"), *ActorGuid.ToString())
}
//In Restore Actors function
FGuid ActorGuid = ISaveInterface::Execute_GetActorId(Actor);

if (LoadedSave->WorldState.DestroyedActorGuids.Contains(ActorGuid))
{
    Actor->Destroy();
    continue;
}
Serialization — Take advantage of serialization and SaveGame tag

Easy saving and loading variables, without the need to add them manually in the SaveGame Object.

//MySaveGame UObject
USTRUCT(BlueprintType)
struct FActorSaveData
{
	GENERATED_BODY()

	UPROPERTY(BlueprintReadWrite, Category = "SaveSystem | Actor")
	FGuid PersistentID;
	UPROPERTY(BlueprintReadWrite, Category = "SaveSystem | Actor")
	FTransform Transform;
	UPROPERTY(BlueprintReadWrite, Category = "SaveSystem | Actor")
	TObjectPtr ActorClass;
	UPROPERTY(BlueprintReadWrite, Category = "SaveSystem | Actor")
	TArray SerializedData;
}

//SaveSubsystem.cpp
//Save
FActorSaveData ActorSaveData = ISaveInterface::Execute_GetSaveData(Actor);

FMemoryWriter MemWriter(ActorSaveData.SerializedData);
FObjectAndNameAsStringProxyArchive Ar(MemWriter, true);
Ar.ArIsSaveGame = true;
Actor->Serialize(Ar);

CurrentSave->SavedActorMap.Add(SAI, ActorSaveData);

//Restore
FActorSaveData SAD = SaveableActorData[ActorGuid];
Actor->SetActorTransform(SAD.Transform);

FMemoryReader MemReader(SAD.SerializedData);
FObjectAndNameAsStringProxyArchive Ar(MemReader, true);
Ar.ArIsSaveGame = true;
Actor->Serialize(Ar);
